Observatory

A local practice ground for distributed-systems debugging and system design. It doesn't run real distributed systems. It simulates the tools you'd use to debug them: dashboards, service maps, per-instance heatmaps, traces, and logs. Think nsys for microservices. Claude writes incident scenarios. You investigate, write a report, and paste it back to be graded.

🔭 Incident Observatory

Open a scenario and debug it: Brief → Service Map → Metrics → Heatmap → Timeline → Traces → Logs → Report.

🧪 Concepts Lab

Interactive visualizations: queueing and the utilization knee, fan-out tail latency, consistent hashing, quorums, LSM trees, caching, isolation anomalies, rate limiting, capacity estimation.

📐 Design questions

Classic system-design prompts in design/questions/. Write your design and send it to Claude for a review against the rubric.

Scenarios

How the loop works

  1. Ask Claude (in this folder): make me a new scenario about <topic>, or just new scenario, medium.
  2. Open observatory.html (double-click it, no server needed) and pick the scenario.
  3. Investigate. Pin evidence (p on a chart), and fill in the Report tab.
  4. Press Copy as Markdown and paste it to Claude. You get graded against the hidden answer key, with feedback, and it's logged in progress/log.md.
